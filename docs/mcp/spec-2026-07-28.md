# MCP 2026-07-28 conformance

daymet-mcp targets the MCP 2026-07-28 specification (stateless core) with the Python `mcp` SDK 2.x
low-level `Server`. The protocol version is taken from the SDK
(`mcp.types.LATEST_PROTOCOL_VERSION`), never written as a literal.

| Feature | How daymet-mcp uses it |
| --- | --- |
| Tools | 8 tools, sorted by name; `daymet_download_area` only over stdio |
| Structured output | Every tool declares an `outputSchema` (JSON Schema 2020-12) and returns the same compact JSON as text and as `structuredContent` |
| Annotations | `title` plus all four hints on every tool |
| Tool `_meta` | `io.daymet-mcp/surface`, `endpoints`, `stdioOnly`, `requiresToken` |
| Result `_meta` | `io.daymet-mcp/upstream` (`requests`, `cacheHits`, `backend`, ...) next to the SDK's server info |
| Errors | Tool failures are results with `isError: true` and `structuredContent.error = {code, message, details, hint?}`; only protocol faults are JSON-RPC errors |
| Size | Results are trimmed to 50 000 bytes along the time axis (`page.truncatedReason = "budget"`); 200 000 bytes is a hard cap |
| Paging | `offset`/`limit` inputs and a `page` object, not MCP cursors |
| Cache hints | public; tools/list 5 min, resources 1 h, prompts/list 24 h, server/discover 5 min |
| Not used | sampling, roots, logging/setLevel, elicitation, progress, sessions, legacy SSE |

## Tests

`tests/test_spec_conformance_2026_07_28.py` drives the server through the SDK client: the tool list
is sorted and size-bounded, every schema validates as JSON Schema 2020-12, every tool is called and
its `structuredContent` validates against its `outputSchema`, text equals structured content,
annotations and `_meta` are present, and unknown resources give `-32602` with `didYouMean`. The
transport tests repeat the calls over a real stdio subprocess and a real HTTP server.
